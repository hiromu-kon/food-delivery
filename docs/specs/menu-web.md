# Web のメニュー閲覧（F-04 / S-C05）

認証済みの有効な注文者が、店舗一覧のカードから `/stores/:storeId/menu` に進む。受付停止中の店舗にも進める。住所の選択・保存・復旧は店舗一覧の既存仕様を保ち、「店舗一覧に戻る」は常に `/` に戻るため、直接開いた場合も利用できる。

## データと状態

既存の型付き API client から `GET /stores/:storeId/menu` を `no-store`・cookie 付きで取得し、公開 schema で応答を検証する。店舗名・説明・住所・最低注文金額・受付状態、カテゴリ名・説明・写真、商品名・説明・税込価格・写真を返却値から表示する。カテゴリと商品は応答の配列順をそのまま保つ。売り切れも価格・説明とともに残し、「売り切れ」の文字と薄い写真で区別する。

カテゴリなしは「メニューはまだ登録されていません」、商品なしのカテゴリは見出しを残して「このカテゴリにはまだ商品がありません」と表示する。読込中は status、失敗は alert と「もう一度試す」を表示する。不正・不存在の店舗は一覧からの選び直しも案内する。401 はログイン、403 はアクセス不可へ移る。メール確認前でも認証ガードと API が許可する閲覧を妨げない。

店舗 ID と注文者 ID で画面を作り直し、店舗変更時に前の店舗データを持ち越さない。再取得時も内容を消して読込状態に戻す。取得の世代を管理し、再取得・画面離脱後の古い成功・失敗・認証応答を破棄する。タブ復帰・履歴復元でも再取得する。

## 配置と操作

Penpot の S-C05 board `b5f6bdf2-dac1-8004-8008-d825d1f5751f` の実 content・appliedTokens を参照する。236px の店舗写真と、左右16px・写真下端から60px重なるのれんを置く。藍色の面、明朝の店名、補助文、96pxの商品写真、16pxの商品間余白と区切り線に既存の semantic tokens・共通部品を使う。写真未登録の商品は写真欄を省略し、URLありで読込失敗した写真には共通の fallback を使う。カテゴリの写真は登録時のみ表示する。

カテゴリは横にスクロールできる名前付き navigation 内のページ内リンクとし、全カテゴリを縦に表示する。見出しには階層とリンク先を持たせる。商品行は表示専用で、追加ボタンやカート操作は作らない。PC は既存の CustomerHeader と最大800pxの本文、390px は既存の Web 上部ナビゲーションと1列本文を使う。長い本文・店名は折り返し、カテゴリ名は横スクロールで切り詰めない。

Penpot のカート・追加操作は F-05 以降のため含めない。API 応答にない配達料・距離は補完しない。注文・支払、画像の登録・保存先、外部画像の検証取得、本番 seed は対象外。

## 確認

Web の表示テストで API 応答の順序・売り切れと価格・写真・空状態を確認し、取得制御テストで不正応答・HTTP エラー・再試行・古いルートや離脱後の認証応答破棄を確認する。専用 PostgreSQL と合成データを使い、production Web でカードからの遷移、カテゴリ順、売り切れ、戻る、空状態、失敗と再試行、セッションガードを確認する。
