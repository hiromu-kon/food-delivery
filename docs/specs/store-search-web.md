# 店舗検索 Web（F03 / S-C04）

## 対象と導線

注文者のホーム `/` にお届け先の切替と、そのお届け先に配達できる店舗一覧を表示する。住所の登録・編集・削除は既存の `/addresses`（S-C10）で行う。メニュー閲覧と注文（F04/F05）は対象外とし、店舗カードは非操作表示にする。

## データと選択

認証済み注文者について、既存の `hc<AppType>` クライアントから Cookie 付き・`no-store` で `GET /addresses` を取得する。その本人住所一覧だけを候補にし、有効な明示選択を優先して選んだ ID を `GET /stores?addressId=…` に渡す。レスポンスは contract の住所・店舗検索 schema で検証する。店舗の配達可否、並び順、距離、受付可否は API の結果を表示し、Web で再計算しない。停止店舗も一覧に残し、API の `canOrder` に従って「受付停止中」を表示する。

明示選択はユーザー ID を含むキーの `sessionStorage` に住所 ID だけを保存する。保存が禁止された環境では表示中の選択を維持する。初期表示、ホームへの再訪、タブ復帰、履歴復元、再試行、住所切替時に住所一覧を取得し直し、保存 ID が欠落・不正・削除済み・他人の住所なら実`isDefault`住所、なければID順先頭へ復旧する。自動復旧先は明示選択として保存せず、先頭に既定の表示を付けない。住所がなければ選択を消し、住所管理への導線を表示する。ユーザーが変わった場合はコンポーネントをユーザー ID で作り直し、別ユーザーの保存キーを読み込まない。

Next.js 16.4 の Cache Components / クライアント側画面保持を考慮し、ホームの古い Server Component payload に住所一覧を埋め込まない。Client Component の Effect の起動・再開時に API を取り直し、focus / pageshow / visibilitychange でも更新する。

## 取得中・失敗時

住所・店舗の取得開始時に前回の店舗を消し、取得中であることを通知する。一連の取得に世代番号を与え、新しい選択・再取得・画面離脱より古い住所応答と店舗応答は成功・失敗とも採用しない。住所一覧の直後に店舗 API が404を返した場合は一度だけ住所一覧からやり直す。繰り返す404や通信・schema・サーバーエラーは再試行を案内する。

401は `/login`、403は `/access-denied` に遷移する。API のアクセス制御を正とし、既存の Server Component の認証と SessionGuard も継続する。店舗が0件の場合と住所未登録の場合を区別し、取得失敗を空一覧として扱わない。

## 表示

既存の StoreCard、NoticeBanner、Button とデザイントークンを再利用する。配達料の目安は domain 公開定数 `defaultCartDeliveryFee` を表示し、確定金額は注文時に確認する旨を示す。最低注文金額と距離は API 値を既存 formatter で表示する。モバイルは1列、広い画面は2〜3列で表示する。「配達できるお店」と取得済み配列の件数「n 店」を表示し、モバイルの左右余白は16px、店舗間隔は24pxとする。

名前があれば住所バーと選択行へ表示し、住所・建物も残す。お届け先は約64pxの AddressBar から Drawer を開いて選ぶ。シート内から `/addresses` へ追加・編集に進める。長い住所は折り返し、固定高で切り取らない。Web の上部メニューとアプリの下部タブの違いは [Web デザイン整合](design-alignment-web.md) を参照。

## 検証

同居する `search-state.test.ts` で不正な選択の復旧、住所未登録、404の限定再取得、認証エラーの伝播と再試行、店舗応答の逆順成功・失敗、離脱中の住所応答の破棄を確認する。API の業務ルールは既存の実 PostgreSQL 結合テストを利用する。実行ログ・画面画像・一時 fixture / harness はリポジトリ外に保存する。
