# 仕様：業務ルール

「初期値」は開発側で置いた仮の値。変えられるようにしておき、運用を始めてから見直す。

## 店舗と配達エリア

| ID   | ルール                                                                                                               | 初期値 |
| ---- | -------------------------------------------------------------------------------------------------------------------- | ------ |
| R-01 | 店舗からお届け先までの直線距離が、店舗の配達半径以内なら配達エリアに入る。配達半径は店舗ごとに運営が設定する         | 3 km   |
| R-09 | 停止中の店舗は、一覧に「受付停止中」と表示し、注文できない。注文を確定する時点でも受付中かを確かめる                 | —      |
| R-10 | 売り切れの商品はメニューに表示するが、カートに入れられない。注文を確定する時点で売り切れの商品があれば、注文できない | —      |

## 金額

| ID   | ルール                                                                                                                                  | 初期値        |
| ---- | --------------------------------------------------------------------------------------------------------------------------------------- | ------------- |
| R-02 | 合計 = 小計 + 配達料。配達料は全店舗で一律の額とする。金額はすべて税込の整数（円）                                                      | 配達料 300 円 |
| R-03 | 1 つのカートには 1 つの店舗の商品だけを入れる。別の店舗の商品を入れようとしたら、カートを空にしてよいかを確かめる。1 商品の数量は 1〜20 | —             |
| R-04 | 小計が店舗の最低注文金額に満たない場合は、注文できない。最低注文金額は店舗ごとに設定する                                                | 0 円          |
| R-13 | 注文時の商品名・価格・配達料を注文に記録する。注文の後にメニューの価格が変わっても、注文の金額は変わらない                              | —             |

金額の計算は `packages/domain` の関数で行い、API と画面の両方から使う。画面は表示のためだけに使い、注文の金額は API が計算した値を正とする。

## 支払いとキャンセル

| ID   | ルール                                                                                                                                                                             | 初期値 |
| ---- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------ |
| R-05 | 注文時に合計を仮売上にする。店舗が受け付けた時点で売上を確定する。店舗が断った場合は仮売上を取り消す。売上の確定に失敗した場合は受付を完了せず、受付待ちのまま店舗に失敗を表示する | —      |
| R-06 | 注文から受付期限までに店舗が受け付けなければ、システムが注文をキャンセルし、仮売上を取り消す                                                                                       | 10 分  |
| R-07 | 注文者は、受付待ちの間だけ注文を取り消せる                                                                                                                                         | —      |
| R-08 | 受付後（調理中・準備完了・配達中）のキャンセルは運営だけができ、配達料を含めて全額を返金する。一部の返金は MVP では扱わない                                                        | —      |

## 配達

| ID   | ルール                                                                                                                                                                      | 初期値 |
| ---- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------ |
| R-11 | 稼働中の配達員は、配達待ちの注文を 1 件選んで担当になれる。先に操作した 1 人だけが担当になる。担当できるのは同時に 1 件まで。配達員は自分で担当を外せず、外せるのは運営だけ | —      |
| R-12 | 担当の配達員は、準備完了の注文だけを「受け取った（配達中）」にできる。注文者に渡したら「配達完了」にする                                                                    | —      |

## アカウント

| ID   | ルール                                                                                                                                                                                    | 初期値 |
| ---- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------ |
| R-14 | 注文者は自分で登録し、メールアドレスの確認が済むまで注文できない。店舗スタッフ・配達員・運営のアカウントは運営が発行する。停止されたアカウントはログインできない。パスワードは 8 文字以上 | —      |
