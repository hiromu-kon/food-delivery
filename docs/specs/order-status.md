# 仕様：注文の状態

## 状態

| 状態       | コード上の名前 | 意味                                             |
| ---------- | -------------- | ------------------------------------------------ |
| 受付待ち   | `pending`      | 注文され、仮売上が済んだ。店舗の受付を待っている |
| 調理中     | `preparing`    | 店舗が受け付け、売上が確定した                   |
| 準備完了   | `ready`        | 調理が終わり、配達員の受け取りを待っている       |
| 配達中     | `delivering`   | 配達員が店舗で受け取った                         |
| 配達完了   | `delivered`    | 配達員が注文者に渡した                           |
| キャンセル | `canceled`     | 取り消された。理由（下表）を記録する             |

配達員が決まっているかどうかは、状態とは別に「担当の配達員」として持つ。調理中・準備完了で担当の配達員がいない注文を「配達待ち」と呼ぶ。

## 遷移

```mermaid
stateDiagram-v2
  [*] --> pending: 注文する（仮売上）
  pending --> preparing: 店舗が受け付ける（売上確定）
  pending --> canceled: 注文者が取り消す / 店舗が断る / 受付期限切れ
  preparing --> ready: 店舗が準備完了にする
  ready --> delivering: 担当の配達員が受け取る
  delivering --> delivered: 担当の配達員が渡す
  preparing --> canceled: 運営がキャンセル（返金）
  ready --> canceled: 運営がキャンセル（返金）
  delivering --> canceled: 運営がキャンセル（返金）
  delivered --> [*]
  canceled --> [*]
```

| 遷移                                  | 操作する人           | 条件                            | 決済         | ルール     |
| ------------------------------------- | -------------------- | ------------------------------- | ------------ | ---------- |
| → 受付待ち                            | 注文者               | R-01〜R-04, R-09, R-10 を満たす | 仮売上       | R-05       |
| 受付待ち → 調理中                     | 店舗スタッフ         | 受付期限内                      | 売上確定     | R-05, R-06 |
| 受付待ち → キャンセル                 | 注文者               | —                               | 仮売上の取消 | R-07       |
| 受付待ち → キャンセル                 | 店舗スタッフ（断る） | —                               | 仮売上の取消 | R-05       |
| 受付待ち → キャンセル                 | システム             | 受付期限を過ぎた                | 仮売上の取消 | R-06       |
| 調理中 → 準備完了                     | 店舗スタッフ         | —                               | —            | —          |
| 準備完了 → 配達中                     | 担当の配達員         | 担当の配達員がいる              | —            | R-12       |
| 配達中 → 配達完了                     | 担当の配達員         | —                               | —            | R-12       |
| 調理中・準備完了・配達中 → キャンセル | 運営                 | —                               | 全額返金     | R-08       |

上の表にない遷移はできない。API は、できない遷移の要求をエラーにする。

## 担当の配達員

| 操作         | 操作する人 | 条件                                                   | ルール |
| ------------ | ---------- | ------------------------------------------------------ | ------ |
| 担当になる   | 配達員     | 注文が配達待ちで、配達員が稼働中かつ担当中の注文がない | R-11   |
| 担当から外す | 運営       | 注文が配達完了・キャンセルではない                     | R-11   |

## キャンセルの理由

| 理由                 | コード上の名前   |
| -------------------- | ---------------- |
| 注文者が取り消した   | `customer`       |
| 店舗が断った         | `store_rejected` |
| 受付期限切れ         | `expired`        |
| 運営がキャンセルした | `admin`          |

## 注文者向け参照 API（F-07）

Cookie または Bearer のセッション認証が必要。確認済みメールアドレスを持つ注文者のみ利用でき、応答は `Cache-Control: no-store` とする。

| エンドポイント    | 応答型（`@repo/contract`）                                          | 用途                                                                                            |
| ----------------- | ------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------- |
| `GET /orders`     | `CustomerOrderListResponse`（`{ orders: CustomerOrderSummary[] }`） | S-C09。進行中を含む自分の全注文を作成日時の降順、同日時は ID の降順で返す。注文がなければ空配列 |
| `GET /orders/:id` | `CustomerOrderDetailResponse`（`{ order: CustomerOrderDetail }`）   | S-C08。自分の注文だけを返す                                                                     |

`CustomerOrderSummary`（別名 `OrderSummary`）は `id`, `storeId`, `storeName`, `status`, `total`, `createdAt`（UTC ISO 8601）を持つ。店舗名は現在の店舗名、金額は注文時の値。
`CustomerOrderDetail`（別名 `OrderDetail`）はさらに `address`, `building`, `fulfillment`（`hand_delivery` / `leave_at_door`）, `dropoffLocation`（`front_door` / `delivery_box` / `other` / `null`）, `subtotal`, `deliveryFee`, `items`（`menuItemId`, 注文時の `name`, `unitPrice`, `quantity`）, `deliveryPhotoUrl`（URL または `null`）を持つ。金額は円の整数。

状態は上表の6種類をそのまま返す。S-C08 の「取り消す」は `status === 'pending'` の間だけ表示する（取消操作 API は F-08）。置き配写真は配達完了後だけ表示する契約だが、現在は写真の永続化が未実装のため `deliveryPhotoUrl` は常に `null`。状態変更日時も未保存のため返さない。

不正な注文 ID は `400 VALIDATION_ERROR`、存在しない注文と他人の注文は同じ `404 NOT_FOUND`。未認証は `401 UNAUTHORIZED`、注文者以外・メール未確認・利用停止は既存の認証ルールに従う。注文・明細とも認証ユーザー ID で絞り込み、決済 ID・Stripe 情報・ユーザー ID・座標・内部処理用の値は返さない。
