# 仕様：お届け先（F-02 / S-C10）

認証済みの注文者が本人のお届け先を登録・一覧表示・取得・変更・削除する。メール確認前も管理できる（注文時のメール確認は R-14）。停止中のアカウントと店舗・配達員・運営は利用できない。

## 入力と保存

| 項目           | API 名         | 制約                                                        |
| -------------- | -------------- | ----------------------------------------------------------- |
| 住所           | `address`      | 前後の空白を除去して1〜200文字。都道府県から番地まで入力    |
| 建物・部屋番号 | `building`     | 前後の空白を除去して100文字以内。登録時の省略は空文字       |
| 配達メモ       | `deliveryNote` | R-15。前後の空白を除去して100文字以内。登録時の省略は空文字 |

文字数は JavaScript の UTF-16 コード単位で数える。null、型違い、NUL文字、未知のキーを拒否する。`userId` と座標の入力も拒否し、所有者は認証済みセッションから取得する。緯度・経度はサーバーから地図サービスに住所だけを渡して求める。建物・部屋番号と配達メモは地図サービスへ送信しない。

配達メモはこのAPIでは所有者だけに返す。担当配達員への開示は今後の注文・配達APIの範囲とする。

## API

| Method | パス             | 成功時                                             |
| ------ | ---------------- | -------------------------------------------------- |
| GET    | `/addresses`     | 200 `{ addresses: [...] }`。ID昇順で本人の住所のみ |
| POST   | `/addresses`     | 201 `{ address: ... }`                             |
| GET    | `/addresses/:id` | 200 `{ address: ... }`                             |
| PATCH  | `/addresses/:id` | 200 `{ address: ... }`                             |
| DELETE | `/addresses/:id` | 200 `{ status: true }`                             |

住所の公開項目は `id`（UUID）、`address`、`building`、`deliveryNote`、`latitude`、`longitude`。所有者IDは返さない。PATCHは指定された項目だけを変更し、未指定項目は保持する。空のPATCHは400。住所が変わらなければ地図APIを呼ばず、住所変更時は測位が成功した後に住所と座標を同一SQLで更新する。

全ルートで既存のセッション認証を使う。Cookie認証による変更は既存のOrigin検査も適用する。すべてのDB参照・更新・削除に所有者条件を付け、他人の住所と存在しない住所は同じ404にする。他人の住所の変更では地図APIも呼ばない。キャッシュは `no-store`。

| 状況                                       | HTTP / code                                            |
| ------------------------------------------ | ------------------------------------------------------ |
| 入力不正・UUID不正                         | 400 `VALIDATION_ERROR`（不正JSONは `INVALID_REQUEST`） |
| 未認証                                     | 401 `UNAUTHORIZED`                                     |
| 別role・停止中                             | 403 `FORBIDDEN` / `ACCOUNT_DISABLED`                   |
| 本人の住所が見つからない                   | 404 `NOT_FOUND`                                        |
| 地図上で住所を一意に特定できない           | 422 `ADDRESS_NOT_FOUND`                                |
| 地図キー未設定                             | 503 `GEOCODING_NOT_CONFIGURED`                         |
| 通信失敗・タイムアウト・不正応答・利用制限 | 503 `GEOCODING_UNAVAILABLE`                            |

## 地図サービス

OpenCage Geocoding API を標準 `fetch` で呼ぶ。公式仕様は[APIドキュメント](https://opencagedata.com/api)を参照。公式の Caching 節で座標の永続保存が許可されているため採用した。

- `OPENCAGE_API_KEY`：サーバー専用キー。未設定時でも一覧・取得・削除・住所が変わらない部分更新は可能。登録・住所変更は設定エラーで失敗し、仮の座標は使わない。
- `GEOCODING_TIMEOUT_MS`：応答本文の受信を含む期限。既定5000ms、1〜30000ms。
- 送信先は `https://api.opencagedata.com/geocode/v1/json` 固定。`countrycode=jp`、`language=ja`、`limit=2`、`no_annotations=1`、`no_record=1` を指定する。リダイレクトと自動再試行は行わない。
- HTTP成功かつ本文 `status.code=200`、結果が1件で `components._type=building`、`country_code=jp` の場合だけ座標を採用する。道路・市区町村などの中心点や複数候補は不明住所として拒否する。緯度は−90〜90、経度は−180〜180の有限な数値に限る。
- 公式仕様上、測位結果は住所の実在や部屋番号を保証しない。日本の住所の網羅性・精度と実キーでの接続は未確認。実運用前に代表的な住所で確認する。
- 住所と座標の保存前に測位を完了させる。失敗した登録では行を作らず、失敗した住所変更では既存の住所・座標・建物・配達メモを保持する。
- URLに住所と鍵が含まれるため、外部例外や応答本文をログ・API応答に渡さない。

## 検証・移行

DBスキーマと drizzle-kit 生成のmigrationをコミットする。本番・開発DBへの適用は行わない。

APIテストは `TEST_DATABASE_URL` にテスト専用DBを指定して実行する。認証と住所のテストは同じDBを初期化するためファイル単位で直列実行する。HTTPを差し替えた実アダプターとPostgreSQLを組み合わせ、座標保存、所有権、ロール、停止、厳密な入力検証、地図の失敗時の原子性を検証する。課金APIの実呼び出しは行っていない。
