# 配達員管理（F-18）

Issue #79 / #80。運営認証の共有契約（`requireSession` → `requireRole(['admin'], true)`、Web の `requireAdminContext` と `AdminSessionGuard`）を使う。

## API

`/admin/couriers` の GET は配達員一覧、POST はアカウント発行。`/:id` の GET・PATCH・DELETE は詳細・編集（停止/再開を含む）・削除。対象が存在しない場合と他ロールの場合は同じ404。応答は no-store。未認証は401、運営以外・停止・メール未確認は403。Cookie 更新は Origin を検査する。

氏名・メール・電話番号を登録し、発行時のみ8〜128文字の初期パスワードを受け付ける。運営が本人のメール確認を済ませた前提で、確認済み courier とハッシュ化済み credential を単一トランザクションで作る。既存メールは409で拒否し、他ロールを昇格しない。入力は strict schema で検証し、role などの指定を拒否する。応答は ID・氏名・メール・電話番号・停止フラグのみ。

更新トランザクションでは運営の現在の権限を共有ロックで再確認する。停止時は既存セッションを削除し、共通認証の disabled 検査で再ログインも拒否する。再開しても削除したセッションは復元しない。削除は物理削除で credential とセッションも削除する。

## Web（S-A06 / S-A07）

`/admin/couriers` に一覧と登録・編集フォームを置く。運営トップから遷移し、氏名・メール・電話番号・初期パスワードを入力して発行する。編集の「アカウントを停止する」で停止・再開する。重複メール・通信失敗は再入力または一覧再読込を案内し、保存中の重複送信を防ぐ。

稼働状態は本ブランチの DB に保存先がないため「未取得」と表示する。稼働中/停止中などの値を捏造しない。削除は API のみ提供する。デザイン照合は別途必要。
