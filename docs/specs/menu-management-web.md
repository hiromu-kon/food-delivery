# 店舗Webのメニュー管理（F-11 / S-S04・S-S05 / Issue53）

`/store/menu` の一覧からカテゴリ・商品を追加、編集、削除する。商品編集では名前・説明・税込価格・カテゴリ・画像URL・表示順・売り切れを変更でき、一覧でも売り切れを切り替えられる。空メニューではカテゴリ登録から案内し、空カテゴリには商品追加を案内する。APIの配列順で表示し、表示順が同じ場合の並びもAPIに従う。

## 認証とAPI

[店舗Web認証](store-auth-web.md) のサーバー認証境界・クライアントguardを使用する。画面のキーに本人と所属店舗を含め、所属の再確認時には以前の編集画面を破棄する。すべて既存の型付きAPI clientを使用し、Cookie付き・no-storeで `/store/menu` の実APIにアクセスする。店舗IDを送信しない。所属条件・他店舗の404・入力範囲・成功応答は [管理API](menu-management.md) を正本とする。成功応答は公開schemaで検証する。401は店舗ログイン、403は利用不可理由付きの店舗ログインへ戻す。

一覧には読込中・空・失敗・再読み込みを用意する。再取得・離脱後の古い一覧応答を破棄する。保存・削除・売り切れ変更は二重送信をロックし、処理中は関連操作を無効にする。成功後は一覧を再取得し、取得失敗を保存成功とは別に表示する。フォームの失敗では入力を維持する。400は入力確認、404は一覧再読み込み、通信や不正応答では保存状態の確認と再試行を案内する。通信失敗後の自動再送はしない。

## 削除と注文

商品削除は対象名と取り消せないことを確認する。カテゴリ削除では、その時点でカテゴリに含まれる全商品も連鎖削除することを明記し、キャンセルを初期フォーカスとする。削除失敗時はダイアログを残してエラーを表示する。メニューの変更・削除は注文や見積もりを更新せず、注文時の商品名・単価・合計は保持する（R-13）。

## 画像

直接ファイルアップロード、署名URL発行、画像変換は未提供。編集フォームは運営が確認・配備した絶対HTTPS画像URLを入力する。空欄で保存すると `photoUrl: null` を送信し、登録を解除する。画像の保存先・ハッシュによる置換・旧画像の削除は [画像の保存先](menu-management.md#画像の保存先) の運用に従う。ローカルHTTP開発では画像なし、または既存のHTTPS配信URLを利用する。メニュー削除で配信ファイルは削除しない。

## 確認

Webテストで実ルート・認証付き送信・204・応答検証・エラー・画像運用の表示を確認する。専用PostgreSQLと合成スタッフ・2店舗・注文スナップショットを使用し、production Webからカテゴリ・商品CRUD、カテゴリ移動、売り切れ、削除キャンセルと連鎖削除、画像解除、狭幅表示を実APIで確認する。他店舗の取得・更新・削除・移動先指定の拒否、無効セッション、API失敗の画面フィードバックも確認する。録画はui-videoのPlaywright/CDPからMP4を作成し、PRに添付する。
