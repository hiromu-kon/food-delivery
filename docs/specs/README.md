# 仕様

要件定義（[docs/requirements/](../requirements/overview.md)）で決めた機能が、どう振る舞うかを書く。

| ファイル                               | 内容                                   |
| -------------------------------------- | -------------------------------------- |
| [order-status.md](order-status.md)     | 注文の状態と遷移                       |
| [business-rules.md](business-rules.md) | 金額・期限・配達エリアなどの業務ルール |
| [screens.md](screens.md)               | 画面一覧と遷移                         |

## ID の付け方

| 接頭辞 | 対象                                               | 例    |
| ------ | -------------------------------------------------- | ----- |
| F-     | 機能（[features.md](../requirements/features.md)） | F-06  |
| R-     | 業務ルール                                         | R-05  |
| S-C    | 注文者の画面                                       | S-C07 |
| S-S    | 店舗の画面                                         | S-S02 |
| S-D    | 配達員の画面                                       | S-D02 |
| S-A    | 運営の画面                                         | S-A03 |
| N-     | 非機能要件                                         | N-08  |

ID は一度付けたら変えない。廃止するときは欠番にする。

## コードとの関係

- 業務ルールを実装したテストは、テスト名の先頭に ID を書く（例: `it('R-06 受付期限を過ぎた注文はキャンセルされる')`）。仕様を変えたときに、直すテストを ID で探せるようにするため。
- API の入出力の項目は、`packages/contract` の Zod を正本にし、ここには書かない。
- 画面の見た目は Penpot を正本にし、ここには画面の目的・項目・遷移だけを書く。

## 変更の仕方

仕様の変更は PR で行い、関係する Issue と、テストを ID で探して一緒に直す。
