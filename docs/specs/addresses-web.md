# Web お届け先管理（S-C10 / Issue #11）

注文者の `/addresses` で、本人のお届け先の一覧・登録・編集・削除を行う。注文時のお届け先選択の永続化、店舗・注文機能は対象外。

## 認証と API

- 既存の `requireCustomer` と `SessionGuard` を利用する。未ログイン・セッション切れは `/login`、停止アカウント・異なる role は `/access-denied` に遷移する。操作 API の 401 / 403 でも同じ遷移を行う。
- 初期一覧は Server Component から `createServerApiClient()` で Cookie を転送して取得する。初期一覧の取得失敗は再読み込み可能な画面として表示する。
- ブラウザの `hc<AppType>` から既存の `/addresses` API へ直接アクセスし、`credentials: include` と `cache: no-store` を指定する。変更要求の Origin はブラウザが Web の origin を付与する。Server Action を経由しない。
- 全ての一覧・変更要求は no-store。本人の行の絞り込み・権限判定・座標決定は API が正本となる。クライアントから `userId`、緯度、経度を送信しない。

## 入力と変更

| 項目             | 制約                                                     |
| ---------------- | -------------------------------------------------------- |
| お届け先の名前   | 任意、前後空白除去後20 UTF16以内（自宅・職場など自由文） |
| いつも使う       | 任意のcheckbox、登録時は未選択                           |
| 住所             | 必須、前後空白除去後 1〜200 文字                         |
| 建物名・部屋番号 | 任意、100 文字以内                                       |
| 配達メモ         | 任意、100 文字以内                                       |

- `addressInputSchema` で登録・編集の入力を検査する。契約どおり NUL 文字も拒否する。ラベル・補助文・`aria-invalid`・関連付けたエラー文を表示し、最初の不正項目にフォーカスする。
- POST は住所・建物・メモ・名前・既定フラグだけを送る。PATCH は正規化後の入力と編集開始時の値を比較し、`addressUpdateSchema` で検査した変更項目だけを送る。変更がない場合は要求を送らず案内する。
- 編集開始時に名前・既定を含む全値を保持し、任意の名前・既定フィールドが省略された差分比較でも保存済み値を維持する。メモ・建物・名前・既定だけの編集は住所を含めないため、再測位を発生させない。任意項目を消す場合は空文字を送る。
- 書込成功時にフォームを閉じて保存済みと告知し、他住所の既定解除も含めて一覧を再取得する。一覧再取得に失敗した場合は古いカードを隠して再読み込みを案内し、同じ登録フォームからの再POSTを防ぐ。追加・編集のキャンセルは要求を送らずフォームを閉じる。

## 削除と競合

- 共通 `AlertDialog` に対象の住所・建物と削除の確認を表示する。キャンセルでは変更要求を送らない。削除成功後にだけ一覧から取り除く。既定解除・既定住所削除時に他の住所へ自動割当しない。
- ref 内の同期ロックで全変更要求の二重送信を防止する。処理中はフォームと編集・削除・再読み込み操作を無効にする。
- 一覧取得に世代番号を付け、後から開始した一覧を優先する。変更開始時にも番号を進め、変更前に開始した古い一覧の成功・失敗を捨てる。遅れた一覧で編集結果を上書きしたり、削除済み行を復元したりしない。

## 失敗時の表示

- 入力不正、書込HTTPエラー、書込通信失敗時は入力と既存一覧を維持し、`role="alert"` で再試行を案内する。成功は `role="status"` で告知する。
- 422 は番地などの住所確認、503 は地図サービスの復旧を待って再試行する案内とする。
- 404 は一覧の再読み込みを案内する。通信失敗では保存結果が不明な可能性もあるため、再送信前に一覧を再読み込みして確認できるよう案内する。自動再送信は行わない。
- 一覧の再読み込み失敗でも表示中の一覧を消さない。画面のフォームも維持する。

## 表示と検証

既存の `AuthShell`・`TextField`・`Button`・`NoticeBanner`・`AlertDialog` とデザイントークンを使用する。非空の名前を16pxのlabelとして表示し、実際の`isDefault`がtrueのカードだけ「いつも使う」Tagを付ける。名前を自動設定せず、先頭を既定と見なさない。住所＋建物は本文、メモは補助文として維持する。住所・建物・メモは長文を折り返し、操作ボタンも狭い画面で折り返す。一覧末尾に全幅 secondary の「お届け先を追加する」を置き、選択時と編集時だけフォームを表示する。編集・削除は文字リンクの階層とし、押下領域を保つ。共通枠と Penpot との差の扱いは [Web デザイン整合](design-alignment-web.md) を参照。

`address-state.test.ts` では差分 PATCH、100文字境界、入力拒否、二重送信ロック、古い一覧の無効化、HTTP・通信エラー案内を検証する。ブラウザ検証は本番ビルドの Web 3116 と専用 API 18796、専用 PostgreSQL 15433 の `food_delivery_test` を使用する。一時ハーネスで既存 `createApp` / 認証 / 住所サービスを起動し、geocoder のみ DI による固定座標・422・503へ差し替える。実地図サービスへの接続・課金 API 呼び出しは行わない。ブラウザの通信中断と応答遅延は Playwright のルーティングで再現し、画面操作・差分 payload・削除キャンセル・認証遷移を確認する。ハーネス・検証ログ・スクリーンショットはリポジトリ外に保持する。
