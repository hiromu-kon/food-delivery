# 仕様：配達を受ける（F-14）

対象は S-D02 の配達待ち一覧、S-D03 の詳細と受注、S-D04 の担当中注文・受け取り・配達完了、S-D05 の配達履歴。

## API

すべて現在のセッション、配達員ロール、メール確認、アカウント停止状態、配達員登録を確認する。Cookie の変更要求には信頼する Origin が必要。レスポンスは `no-store`。

| メソッド | パス                          | 結果                                                            |
| -------- | ----------------------------- | --------------------------------------------------------------- |
| GET      | `/courier/orders`             | 調理中・準備完了で担当者なしの注文。休止中は空配列              |
| GET      | `/courier/orders/current`     | 本人が担当する調理中・準備完了・配達中の注文、または null       |
| GET      | `/courier/orders/:id`         | 配達待ち、または本人が担当する注文の詳細。他の担当者の注文は404 |
| POST     | `/courier/orders/:id/accept`  | 本人を担当者として保存し、詳細を返す                            |
| POST     | `/courier/orders/:id/receive` | 担当者が準備完了の注文を受け取り、配達中にする                  |
| POST     | `/courier/orders/:id/deliver` | 担当者が配達中の注文を配達完了にする                            |
| GET      | `/courier/orders/history`     | 本人が配達完了にした注文を新しい順に最大100件返す               |

一覧は注文日時・IDの昇順。店舗名と、保存済み店舗座標から注文時のお届け先座標までの直線距離（メートル）を返す。端末の現在地・道路距離は使わない。詳細は店舗住所、お届け先、注文時の商品名・価格・数量、受け取り方法を表示する。配達メモは担当する本人にだけ返し、担当前はキーを含めない（R-15）。決済情報・注文者のアカウント情報は返さない。

## 担当の保存（R-11）

`orders.courier_id` に担当配達員のユーザー ID を保存する。F-19 の注文管理と共通のカラムを使い、配達員登録は `couriers` で再確認する。担当時の注文進捗は変更しない。

受注はトランザクション内で現在の利用者と配達員登録を再確認してロックし、配達員行と注文行のロックで同一配達員の複数受注と同じ注文の取り合いを直列化する。調理中・準備完了・配達中の担当者には部分一意インデックスも設ける。配達完了・キャンセルの担当履歴は保持し、次の受注を妨げない。

休止中は `COURIER_UNAVAILABLE`、別の担当中注文がある場合は `COURIER_BUSY`、他の担当者が決まった場合や配達待ちでなくなった場合は `ORDER_ALREADY_ASSIGNED`（いずれも409）。存在しない注文は404、UUID形式不正は400。本人の担当中注文への再送は、休止中でも同じ担当結果を返す。F-14 API は担当解除と外部決済を実行しない。

## 受け取り・配達完了・履歴（F-15）

受け取りは担当者本人の `ready` 注文だけを `delivering` にし、配達完了は同じ担当者の `delivering` 注文だけを `delivered` にする。注文行をロックして状態を検証し、更新と `order_status_history` の記録を同一トランザクションで行う。同じ操作の再送は成功として扱い、履歴を重複作成しない。担当外・存在しない注文は同じ404、許可されない状態遷移は409。

配達履歴は本人が担当した `delivered` の注文に限り、配達完了時刻・店舗名・合計金額を最大100件、新しい順で返す。置き配写真のアップロード・保存先はまだ実装していないため、この API は写真を受け取らず、注文者 API の `deliveryPhotoUrl` は引き続き `null`。

## アプリ

稼働中のホームに配達待ち一覧を表示し、選択すると詳細を表示する。「担当になる」の成功後は担当中の配達を表示する。競合や対象消失は一覧に戻して理由を知らせる。通信失敗は成功扱いにせず、「一覧・担当中の配達を再確認」で保存済みの結果を取得できる。

担当中の注文はホーム再表示・アプリ復帰時にも取得する。二重操作を防ぎ、画面離脱・休止・稼働切替・利用者変更で古い非同期結果を破棄する。画面を離れると AppState の購読を解除する。
