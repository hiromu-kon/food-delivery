# 注文状況・履歴（注文者アプリ / F-07・F-08）

S-C09 は下部タブの「注文履歴」から開く。API の作成日時降順を保ち、店舗名・状態・注文日時・合計を表示し、行全体から S-C08 へ移る。空の履歴ではお店を探す操作を案内する。S-C07 の注文完了からも注文状況へ移れる。

S-C08 は店舗名・状態・既存 OrderSteps・注文日時と番号・お届け先・受け取り方法・明細・小計・配達料・合計を表示する。置き配かつ配達完了かつ API が写真 URL を返す場合だけ写真を表示する。受付待ちだけ「取り消す」を表示し、ネイティブの確認ダイアログで確定してから送信する。送信中はボタンを無効にし、コントローラーでも二重送信を防ぐ。

既存 AppHeader、ScreenShell、StatusLabel、EmptyState、Button とコードの token を使う。本文は左右16px、詳細の区切りは gap20px、履歴のカードは padding16px・gap12px。長文は折り返して伸長し、safe area・スクロール・下部タブを保持する。Penpot 接続は今回の作業環境では利用できず、実デザインとの直接照合は未実施。

SessionController の Bearer 認証と契約の応答スキーマを利用する。初回 loading・失敗と再試行・履歴0件・見つからない注文を表示する。詳細の取得完了から5秒後に次を取得し、失敗時も再取得する。画面離脱・バックグラウンド移行・認証変更時はタイマーと旧応答を無効化し、再表示時に再取得する。認証変更時には取得済みデータを破棄する。再取得の通信失敗中は直前の内容とエラーを表示するが、400/404 では詳細を破棄する。

## 受付前の取消（F-08 / R-07）

`POST /orders/:id/cancel` の契約を使い、200 の検証済み応答でのみ注文と仮売上の取消完了を案内する。409 では取消操作を止め、受付済みなど取消不可の状態であることを案内して詳細を再取得する。再取得に失敗してもその画面で取消を再送しない。400/404 は詳細を消し、401/403 は既存のセッション失効処理に委ねる。

503・通信断・応答の検証失敗では取消と仮売上の取消の完了を未確認と表示する。GET の `canceled` は仮売上の取消完了を意味しないため、それだけで成功表示に変えない。同じ注文への取消再試行を残す。送信前にユーザーIDと注文IDをキーに未確認マーカーを AsyncStorage に保存し、画面再表示・アプリ再起動後も再試行を復元する。200 または取消不可・見つからない応答でマーカーを削除する。保存失敗時は送信しない。マーカーの削除に失敗した場合も未確認として同じIDで再照合する。

取消開始時に古いGET応答を無効にし、取消処理中はポーリングを止める。完了後は最新の詳細を取得して5秒ポーリングへ戻る。画面離脱・認証変更後に届いた取消応答はその画面へ反映しない。古い確認ダイアログから別の注文を取り消すことも防ぐ。
