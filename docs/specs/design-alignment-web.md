# Web のデザイン整合（S-C01〜05・08〜13）

Penpot の「20 デザイン 注文者」と「03 コンポーネント」を配置・状態の参照元とし、色・書体サイズ・行高の値は `packages/design-tokens/theme.css` を正とする。本文行高1.6を、Penpotの短文見本の高さに合わせて縮めない。長文は折り返して伸び、画面全高・カード全高・シート全高を見本に固定しない。

## 共通枠と Web 固有ナビゲーション

認証・住所・アカウント・法務画面はモバイルで56pxの画面名ヘッダーと左右16pxの本文を使う。ログインのみ左右24px、30pxの Zen Old Mincho ブランドと「近くのお店の料理を、お届けします」を置く。主CTA、パスワードを忘れた方向けの操作、はじめての方向け案内の順とする。

認証済み画面は PC で CustomerHeader を使い、店舗一覧の最大幅は1200pxとする。モバイルでは「お店を探す」「注文履歴」「カート」「アカウント」の上部メニューを残す。これは `screens.md` の Web 仕様に基づくナビゲーションで、Penpot アプリ画面の下部 TabBar と位置・占有高が異なる。公開の規約・プライバシーポリシーにはフッターから移れる。

## 各画面

- 会員登録は氏名に「配達員にお伝えします」、メールに「確認のメールを送ります」を表示する。単一チェックの「利用規約とプライバシーポリシーに同意する」を、送信時に `termsAccepted: true` と `privacyAccepted: true` の両方へ明示的に展開し、現行の文書版も送る。未同意では送信しない。文書リンクは入力を保つため新しいタブで開く。
- 店舗一覧は AddressBar → 住所選択シートを使い、住所追加・編集にも進める。選択IDの sessionStorage、復帰再取得、削除済みIDからの復旧、古い応答の破棄は維持する。見出しは22pxの「配達できるお店」、件数は右隣に8px空け、API 応答の店舗配列の長さを表示する。「配達料は目安」「注文は準備中」の説明は一覧末尾に置く。
- 住所一覧はカード間12px、末尾の全幅 secondary CTA から登録フォームを開く。編集もフォームを開き、保存成功またはキャンセルで閉じる。エラー時は入力を維持し、削除は確認ダイアログを使う。住所の名前は任意の自由文（20 UTF16以内）で表示・保存し、非空なら16px labelとする。既定checkbox「このお届け先をいつも使う」を用い、APIの実isDefaultだけ「いつも使う」Tagを表示する。先頭住所を「自宅」「いつも使う」とみなさない。
- アカウントはコンパクトな登録情報、補助情報としてのメール確認状態、ListItem による住所・規約・プライバシー・ログアウトを使う。住所行のvalueには取得できた実既定住所の非空の名前を表示し、未設定・失敗時は空とする。長いvalueは折り返し、固定高で切り取らない。登録情報変更・退会はお問い合わせ窓口への連絡を案内する。窓口URLが未確定のため架空の送信先は置かない。
- 法務の節見出しは18px。本文は `docs/legal/terms.md`・`privacy.md` の全文を維持し、Penpot の短い例文で置き換えない。

## 共通部品

TopBar の受付停止は warning 面・文字・境界とする。境界は semantic token `border-warning`（yellow300）を使う。再開経路は未実装の操作を案内しないよう現行文言を維持する。

MenuItem の写真未登録では写真欄を省略する。URLありの読み込み失敗は灰面と料理アイコンを残す。StoreCard の未登録fallbackは維持する。

OrderSteps は24pxの円・線領域で中心を揃え、ラベルのコード行高を維持する。Penpot の bar frame 12/16pxと見本全高38pxへの一致は求めず、現在円の外径24px・内径16pxと線の中心を保つ。

Drawer は40pxのhandle押下領域と閉じるボタンを維持し、handle領域の後の追加12px paddingを除いて見出しとの空きを整理する。見えるhandleと見出しの間隔は16px。Escape・フォーカストラップ・復帰・ドラッグ・safe area・内容スクロールを保つ。Select の popup はcontrolから8px空ける。

これらは主要属性の整合方針で、全variantの画素一致を意味しない。PCの段組、実文書・補助文の行数、Webメニューの高さ、操作領域を含むシート全高はアプリ見本と異なる。

S-C05 のメニュー閲覧は [menu-web.md](menu-web.md) を参照する。商品価格は売り切れでも表示する。F-05 の追加操作と S-C06 は [cart-web.md](cart-web.md) を参照する。

## 注文状況・履歴（S-C08・09）

既存の AuthShell の最大幅・左右16pxと共通の StatusLabel・OrderSteps を使用する。履歴には注文日時・店舗名・状態・APIの合計を表示し、行から詳細へ進む。詳細は状態、注文内容、小計・配達料・合計、配達完了後の置き配写真を表示する。写真が未提供の場合はその旨を表示する。注文完了画面の操作も詳細へつなぐ。取消操作は F-08 の対象とする。

詳細を開いている間は15秒間隔で再取得し、画面を離れると通信とタイマーを停止する。取得失敗時は再読み込みを案内し、更新失敗では取得済みの内容を残す。認証切れ・権限エラーは既存の認証画面へ移動し、注文が見つからない場合は内容を消して履歴から選び直すよう案内する。長文・メニューは狭幅で折り返し、固定高で切り取らない。Penpot の実ボードとの照合は未実施。S-C08 の取消操作は合成データを使うローカル実 API とブラウザーで確認する。

## 受付前の取消（F-08 / S-C08 / R-07）

詳細 API が `pending` を返す間だけ「取り消す」を表示する。確認ダイアログで「取り消さない」を選ぶと通信せず閉じる。「注文を取り消す」で本文なしの `POST /orders/:id/cancel` を送り、通信と最新状態の取得が終わるまで操作を無効にする。取消前から進行中の取得は、明示的な再取得で中止し、古い応答で状態を戻さない。

成功・失敗のどちらでも詳細 API を再取得する。200 の契約に一致する本人注文 ID の応答だけを取消確認済みとして表示し、409 では受付済みなどで取り消せない旨を案内する。401・403 は既存の認証・アクセス拒否画面へ移動し、404・不正 ID では再取得により注文内容を消す。再取得に失敗した場合は取得済み表示を残し、取消操作を無効にして「再読み込み」を案内する。

503・通信断・応答不正は成功表示にしない。取消リクエストの直前に注文 ID をタブの sessionStorage に保存し、確認済み200または確定的な400・401・403・404・409で解除する。API が `canceled` を返しても未確認の記録がある場合は、決済の取消確認が必要と表示し、「決済取消を再確認」から同じ API を再送できる。これは新たな注文取消ではなく決済の復旧操作である。再読み込み・詳細への戻りでも同じタブでは復旧できる。ストレージが利用できなければ表示中のメモリー内で維持する。

詳細 API は取消理由・決済確認日時を返さないため、別タブ・別端末・タブを閉じた後に未確認状態を復元することはできない。任意のキャンセル注文を未確認と推測せず、API の契約拡張または運用による確認が必要となる。
