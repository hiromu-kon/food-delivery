# 注文者アプリの店舗検索（F03 / S-C04）

認証済みの注文者のホームで、お届け先の切替と配達エリア内の店舗一覧を表示する。住所は本人の `GET /addresses` の結果だけから選び、店舗は `GET /stores?addressId=<UUID>` の結果をその順序で表示する。距離・配達範囲・受付可否はアプリで再判定しない。

## 表示と操作

- 有効な明示選択を優先し、未選択または選択住所の削除時はisDefault=trueの住所、なければID昇順の先頭を選ぶ。自動選択を明示選択として固定しない。同じ画面インスタンスでは明示選択を維持し、削除されたIDの記憶は破棄する。選択を端末へ永続化しない。
- 64pxを最小高とする住所バーから既存の BottomSheet を開き、非空のラベル・住所・建物名を表示して切り替える。シート末尾の「お届け先を追加する」は既存の S-C10 `/addresses` を開き、登録・編集を行える。未登録なら登録を案内し、店舗検索は送らない。
- 取得中は読み込み表示にする。住所切替・再取得を開始した時点で古い店舗を消し、新しい結果と混在させない。
- 店舗は既存の StoreCard で表示する。API の `canOrder: false` の店舗も残し「受付停止中」と表示する。最低注文金額・距離・写真は応答値、配達料の表示は domain の `defaultCartDeliveryFee` を使用する。
- 住所があるが検索結果が空の場合は配達できる店舗がない旨を表示する。通信失敗・不正応答はエラーと再試行を表示し、再試行では住所一覧から取り直す。住所が検索直前に削除された場合の404も再読み込みを案内する。
- F04 メニュー・F05 カートは範囲外。店舗カードは非操作表示とし、メニュー・注文機能が準備中である旨を案内する。未実装ルートへ遷移しない。

## 認証・更新の整合性

`hc<AppType>` と contract の応答 schema を利用する。すべての住所・店舗リクエストは `SessionController.authenticatedRequest` を通し、Bearer を公開 state・画面 props に持たせない。Cookie 認証に依存せず `credentials: omit` / `cache: no-store` で通信する。

Controller は住所一覧取得と店舗検索を共通の世代番号で管理する。新しい選択・focus・セッション変更・画面破棄の後に到着した古い応答は反映しない。画面を離れた時点で表示データを消し、focus 復帰で住所一覧と店舗を取り直すため、S-C10 で編集・削除した住所の古い店舗が残らない。

既存のセッション監視に接続し、ログアウト・別ユーザー・401/403 による失効では住所・店舗・選択を消去する。バックグラウンドからの認証再確認中もデータと進行中の結果を無効にし、認証確認が成功した後、focus 中の画面だけ最新住所と店舗を再取得する。同一ユーザーの再確認では明示選択した住所IDだけを保持し、新しい一覧に存在する場合に再選択する。失効後のログインへ選択を引き継がない。

## 検証

`features/stores/store-search.test.ts` で選択、停止店、未登録・空結果、通信失敗と再試行、店舗・住所の逆順応答、住所編集・削除後の focus 復帰、ログアウト・別ユーザー、バックグラウンド認証再確認を検証する。`api/stores.test.ts` では HTTP のパス・クエリ・Bearer・Cookie 非使用・キャッシュ設定・contract 検証と401/403によるセッションおよび表示データの失効を検証する。

UI の実機操作・画面画像、実 API/DB での確認条件は PR の検証記録に記載する。製品コードにモック・固定座標・架空店舗データは含めない。

アカウントの住所導線はfocus時に本人の住所一覧を取得し、既定住所の非空ラベルだけを補助表示する。未設定・取得失敗では補助表示を省略し、導線を維持する。focus終了や認証状態変更で古い応答を無効にし、失効時は個人情報を残さない。長いラベルは折り返すため、共通ListItemのtrailingへ幅上限と縮小を指定したTextで表示する。
