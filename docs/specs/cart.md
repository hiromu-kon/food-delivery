# 仕様：カート（F-05）

業務ルールは [R-02〜R-04](business-rules.md) を参照する。共通の純関数を `@repo/domain` から公開する。

## 入力と操作

`Cart` は `restaurantId`・`productId`・税込単価 `unitPrice`・`quantity` を持つ商品の読み取り専用配列。空配列が空カートを表す。商品名など表示専用の情報は呼び出し側で管理する。

- `addCartItem(cart, item)` は同店舗の商品を追加し、同商品なら数量を加算して入力された単価に更新する。合算した数量が20を超える場合は拒否する。
- 別店舗の商品なら `confirmation-required` と元のカートを返す。呼び出し側がカートを空にする確認を取り、`{ confirmRestaurantChange: true }` を指定して再実行した場合だけ、新店舗の商品で置き換える。キャンセル時は元のカートを保つ。
- `setCartItemQuantity(cart, productId, quantity)` は数量を変更する。既存の `getCartQuantityControls` に合わせ、0は削除として扱う。商品追加の数量0は拒否する。
- `removeCartItem` は商品を削除し、`clearCart()` は空配列を返す。存在しない商品の変更・削除はカートを変更しない。

入力の配列・商品は変更しない。操作成功は `updated`、不正入力は `invalid` と理由を返す。通常の店舗切替確認や数量上限のために例外やHTTPエラーコードを追加しない。

## 金額と最低注文金額

`calculateCartTotals(cart, deliveryFee = 300)` は小計・配達料・合計を返す。小計は単価×数量の和、合計は小計＋配達料。空カートは配達料も含め0円とする。単価・配達料・最低注文金額は0以上の安全な整数円で、乗算・加算の結果が安全な整数でなければ `invalid` を返す。端数処理や税率の計算はしない。

`checkCartOrderability(cart, minimumOrderAmount = 0)` は配達料を含めず、小計と店舗ごとの最低注文金額を比較する。

| status          | 意味                                       | shortfall              |
| --------------- | ------------------------------------------ | ---------------------- |
| `orderable`     | 空でなく、小計が最低注文金額以上           | 0                      |
| `below-minimum` | 小計が最低注文金額未満                     | 最低注文金額−小計      |
| `empty`         | 空カート（最低注文金額0でも注文不可）      | 最低注文金額           |
| `invalid`       | 不正入力、または計算結果が安全な整数でない | なし（`reason`を返す） |

ここでの注文可能判定はR-04の金額条件だけを扱う。店舗の受付・在庫・認証などはAPIで別に確認する。

すべての操作・計算で、復元したカートの店舗混入、商品重複、数量1〜20の逸脱、不正単価も検証する。`clearCart()` は入力を受け取らず、破損したカートからも空状態へ戻せる。

## 注文金額の正本

クライアントでも表示用に同じ計算関数を使えるが、クライアントが渡した単価・小計・合計を注文の正本にしてはならない。注文時はAPIが信頼できる保存先から商品価格・所属店舗・最低注文金額・配達料を取得し、数量と商品IDを検証して再計算する。この変更では注文保存・決済・Stripe連携は実装しない。
