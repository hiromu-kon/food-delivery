# F-13 配達員ログイン・稼働状態

対象は S-D01、S-D02 の稼働切替、S-D06。注文一覧・受注・配達操作は F-14 以降で扱う。

## 認証と本人情報

運営発行済みのメール確認済みアカウントで共通の `POST /auth/sign-in/email` を利用する。公開登録は引き続き customer のみ。配達員アプリはログイン直後と端末保存セッションの復元時に `GET /courier/me` を呼び、配達員登録まで確認してからホームを表示する。配達員以外・登録なしの場合は受け取ったセッションを破棄する。

`GET /courier/me` は現在の利用者の氏名・メール・電話番号・ロール・メール確認状態と `courier.isAvailable` を返す。未認証・無効・期限切れ・ログアウト後は401、停止・メール未確認・配達員以外・配達員登録なしは403。各取得・更新で現在の users と couriers を照合する。応答は `no-store`。

## 稼働状態

`couriers.userId` は users への一対一の参照。初期状態は休止中（`isAvailable: false`）。`PATCH /courier/availability` は `{ isAvailable: boolean }` のみを受け付け、本人の状態を指定値に保存する。IDの指定や文字列の真偽値は400。更新時にも現在のロール・停止・メール確認状態をDBで照合する。同じ値の再送は同じ状態になる。

アプリは保存成功時にだけ表示を更新する。結果不明の通信失敗では状態を未確認に戻し、「稼働状態を再確認」でAPIの保存値を取得してから切り替える。ログアウトで稼働状態は変更しない。次回ログインでも保存値を取得する。

## 端末セッション

署名付き Bearer を `expo-secure-store` に保存する。API通信は `src/api/` の `hc<AppType>()` を経由し、Cookie に依存しない。アプリ復帰時に認証を再確認する。停止や失効を検出したら端末保存を削除し、ログインへ戻す。通信障害だけでは保存済みセッションを削除せず再試行を案内する。

ログアウトは端末保存を削除してサーバーセッションを失効させる。サーバーに接続できなくても端末からのログアウトは完了するが、サーバー失効は未完了になり得る。端末保存の削除失敗はログアウト完了にせず再試行を案内する。
