# デザイン

画面の見た目と言葉の決まり。見た目そのもの（トークンの値、コンポーネント、ワイヤーフレーム、デザイン）は Penpot を正本にし、ここには理由と、実装で必要なことを書く。実装でトークンをコードに移したあとは、コードを正本にする。

| ファイル                                 | 内容                                                   |
| ---------------------------------------- | ------------------------------------------------------ |
| [tone-and-manner.md](tone-and-manner.md) | ブランドの性格、方向性、文言のルール、写真、避ける表現 |
| [tokens.md](tokens.md)                   | トークンの構成と名前の付け方、値の一覧                 |
| [components.md](components.md)           | コンポーネントの一覧、shadcn/ui との対応、実装の注意   |

## Penpot のファイル構成

ファイルは「Food Delivery」の 1 つ。Penpot の MCP はつないだ 1 ファイルしか操作できないため、部品集と画面を分けない。

| ページ            | 内容                                                                                   |
| ----------------- | -------------------------------------------------------------------------------------- |
| 00 表紙           | ファイルの目次                                                                         |
| 01 トンマナ       | 性格のキーワード、方向性、文言のルールの要点                                           |
| 02 トークン       | 色・文字・余白・角丸・影の見本                                                         |
| 03 コンポーネント | コンポーネントと、その状態・大きさ                                                     |
| 04 画面遷移図     | 利用者ごとの画面の流れ。矢印に操作の名前と条件、ダイアログも載せる                     |
| 10〜13 WF         | 注文者・店舗・配達員・運営ごとのワイヤーフレームと注記。矢印は引かず、流れの順に並べる |
| 20〜23 デザイン   | 同じ利用者ごとのデザイン。画面はワイヤーフレームと同じ順番・同じ位置に並べる           |

ワイヤーフレームとデザインのページを分けるのは、お客様の承認を段階ごとにもらうため。どちらに対するコメントかを明確にし、画面を同じ位置に並べて見比べられるようにする。

## デザインを作る範囲

| 利用者 | 作るもの                                                                   |
| ------ | -------------------------------------------------------------------------- |
| 注文者 | 全画面のデザイン                                                           |
| 配達員 | 全画面のデザイン                                                           |
| 店舗   | 全画面のデザイン。見た目より、使いやすく迷わないことを優先する             |
| 運営   | デザインは作らない。ワイヤーフレームとコンポーネントの組み合わせで実装する |

## 進め方

1. 画面遷移図で、画面の数と流れを決める。
2. ワイヤーフレームで、画面の構成を決める（白黒）。
3. トンマナ・トークン・コンポーネントを決める。
4. コンポーネントを組み合わせて、デザインのページにワイヤーフレームと同じ並びで画面を作る。
5. 承認されたら、トークンをコードに移し、コンポーネントを実装する。
