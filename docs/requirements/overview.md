# 要件定義：概要

このサービスで何を実現するか、どこまで作るかをまとめる。お客様の役は立てていないため、事業の前提は開発側で置いた仮定であり、「前提と制約」に明記する。

## 背景と目的

地域の飲食店の多くは自前の配達手段を持たず、デリバリーに対応できていない。地域で新しくデリバリー事業を始める事業者が、地域の飲食店・配達員・注文者をつなぐサービスを提供する。

| 利用者 | 実現したいこと                                                       |
| ------ | -------------------------------------------------------------------- |
| 注文者 | 近くのお店の料理を Web やアプリで注文し、届くまでの状況を確認できる  |
| 店舗   | 自前の配達員を持たずに、デリバリーの注文を受けられる                 |
| 配達員 | 空いた時間に、近くの配達を受けて届けられる                           |
| 運営   | 店舗と配達員を管理し、注文のトラブル（キャンセル・返金）に対応できる |

## MVP の到達点

注文者・店舗・配達員・運営の 4 者が、画面の操作だけで「注文 → 店舗の受付 → 調理 → 配達 → 配達完了」を一通り終えられること。

## 範囲

MVP に含める機能は [features.md](features.md) の優先度「MVP」のもの。次のものは MVP に含めず、後のフェーズで扱う。

| 後のフェーズ                         | MVP での扱い                                           |
| ------------------------------------ | ------------------------------------------------------ |
| プッシュ通知・メール通知             | 画面を開いている間、一定間隔で状態を取り直して表示する |
| 店舗・配達員への売上の支払い（精算） | システムの外で運営が行う                               |
| 配達員の報酬の計算                   | システムの外で運営が行う                               |
| 配達員の現在地の地図表示             | 状態（配達中など）だけを表示する                       |
| 営業時間による受付の自動切替         | 店舗が手動で受付中・停止中を切り替える                 |
| 商品のオプション（トッピングなど）   | 扱わない                                               |
| クーポン・評価・売上レポート         | 扱わない                                               |
| 予約注文                             | 扱わない。注文はすぐに店舗へ届く                       |
| 現金払い                             | 扱わない                                               |
| 複数の提供エリア                     | エリアは 1 つ                                          |

## 前提と制約

| 項目       | 前提                                                                                         |
| ---------- | -------------------------------------------------------------------------------------------- |
| 提供エリア | 1 つの市区町村                                                                               |
| 店舗       | 地域の飲食店。運営が登録する（店舗の自己登録はしない）                                       |
| 配達員     | 運営が登録した個人。いつ稼働するかは配達員が決める                                           |
| 支払い     | クレジットカードのみ。決済代行は Stripe を使い、カード番号はこのシステムで持たない           |
| 言語・通貨 | 日本語・日本円。価格は税込で表示する                                                         |
| 提供形態   | 注文者は Web とアプリ（iOS・Android）、店舗と運営は Web、配達員はアプリ                      |
| 住所と位置 | お届け先の住所から緯度・経度を求める地図サービスを使う。どのサービスを使うかは実装時に決める |
| 開発体制   | デザイナーはいない。デザインはエンジニアが AI を使って Penpot で作る                         |
