# 要件定義：非機能要件

IPA「非機能要求グレード」の大項目に沿って、MVP での目標を書く。数値は開発側で置いた目標で、運用を始めてから見直す。

| ID   | 大項目       | 要件                                                                                                                  |
| ---- | ------------ | --------------------------------------------------------------------------------------------------------------------- |
| N-01 | 可用性       | 稼働時間の保証（SLA）は設けない。障害時に注文の状態と決済の状態が食い違わないことを優先する                           |
| N-02 | 可用性       | データベースは 1 日 1 回以上バックアップし、7 日分を残す                                                              |
| N-03 | 性能・拡張性 | 店舗一覧・メニュー・注文状況の表示は、通常の通信環境で 2 秒以内に始まる                                               |
| N-04 | 性能・拡張性 | 想定する規模は、店舗 100 店・配達員 50 人・1 日の注文 1,000 件まで                                                    |
| N-05 | 運用・保守性 | API のログに、リクエストごとの ID（`x-request-id`）を残し、注文 ID と決済 ID から追えるようにする                     |
| N-06 | 運用・保守性 | 決済代行（Stripe）との通信の失敗は、運営が気づける形で記録する                                                        |
| N-07 | 移行性       | 新規のサービスのため、既存データの移行はない                                                                          |
| N-08 | セキュリティ | カード番号はこのシステムで受け取らず、Stripe の画面部品で入力してもらう                                               |
| N-09 | セキュリティ | パスワードはハッシュ化して保存する。注文者・店舗スタッフ・配達員・運営は、それぞれ自分の権限の画面と API だけを使える |
| N-10 | セキュリティ | 個人情報（氏名・住所・電話番号・メールアドレス）をログに出さない                                                      |
| N-11 | システム環境 | 注文者・配達員のアプリは、iOS と Android のそれぞれ直近 2 つのメジャーバージョンに対応する                            |
| N-12 | システム環境 | Web は Chrome・Safari・Edge の最新版に対応する。注文者向けはスマートフォンの画面幅でも使える                          |
